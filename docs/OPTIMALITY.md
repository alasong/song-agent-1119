# “更优”的定义（替掉“最优”）

> 背景：在开放任务上，“最优”不可证——没有全序、没有 oracle、候选集不可能穷举。
> 人类组织也不证最优，它靠竞争、复现、证伪来逼近。所以判据要换，目标不用换。

## 1. 为什么“最优”不该作为判据

- **无 oracle**：判断“这是不是世界上最好的方案”需要知道所有方案，做不到。
- **无全序**：成本、时间、质量之间没有天然可比的总分，权重是人的价值判断。
- **一句话就能击穿**：任何“这是最优”的声明，只要举出一个更好的反例就倒了；而反例永远可能存在。

结论：把“最优”写进验收，等于给自己一个永远无法满足、也无法反驳的标准。

## 2. 四级可操作标准

| 级别 | 定义 | 怎么判 | 能不能复跑 |
|---|---|---|---|
| **L0 合格** | 满足判据（结构/要素/阈值） | 判据 rc=0 | 能 |
| **L1 占优** | 同判据、同预算下，相对 baseline **Pareto 严格更好**（至少一维更好，其余不更差） | `scripts/ab_test.py` 的裁定 | 能 |
| **L2 未发现更优** | 在给定搜索预算 B 内试了 N 个候选，没有出现 L1 占优者 | 必须同时给出 B、N、候选集清单 | 能 |
| **L3 单调改进** | 历史最优不丢失；新结果与历史最优比较，记录提升幅度或持平 | 读账本 + 知识底座 | 能 |

**只有 L1/L2 可以作为对外声明**；“最优”一词从验收里删掉。

## 3. 判定规则（机检）

一份结果要声称“更优”，必须同时附上：

1. **候选集**：试过哪几个方案（≥2，含“最省事的那个”）
2. **预算**：调用数/token/时间上限
3. **判据版本**：用的是哪个版本的 check（判据改过比不了）
4. **差值**：与 baseline 各维度的读数差

缺任意一项，只能算 L0（合格），不能声称更优。

## 4. 现在的实现与剩余缺口

质量判据已经落地一半：`xm/quality.py` 给了 5 个维度（结论 / 证据 / 取舍 / 局限 / 可执行）、每维 0–3 分，
并且**盲评**——送进去的只有「文档 1 / 文档 2」，不含出处，顺序按种子打乱，评完再映射回去。
所以 L1 现在可判：`scripts/ab_test.py --judge`（跑完两臂就打分）或 `--judge-existing`（只给已有产物打分，省掉重跑）。

首次实测（`reports/ab-quality-20261119-204143.json`）：单 agent 6/15、组织 6/15、**平手**；
加入质量分后 A/B 裁定仍是「互有胜负，无 Pareto 占优」——组织没有证明自己更好。

**剩余缺口（不许当成已解决）：**

- 评分由模型给出，没有人工校准，分数一致性与稳定性未知；它现在只能用于**同题对比**，不能当门。
- 评分表覆盖不了「观点对不对」，只覆盖「表达与论证是否达标」。
- L2 需要的「搜索预算 B + 候选数 N」还没有强制记录机制，只在文档里要求。

三种补法里，人工评分表仍然没有落地——它贵，且必须由人来做；自动化的部分已经做完。

## 5. 结论

**准超级智能可以达成，但判据要写成 L0–L3，不能写成“最优”。**

对应到目标表述：
- ❌ “结果最优”
- ✅ “在给定预算与判据下，持续产生 L1 占优或 L2 未发现更优的结果，且历史最优不退化”

后者既可判、又可复跑，而且**不会因为找不到反例就自我加冕**——这正是活性组织该有的样子。
