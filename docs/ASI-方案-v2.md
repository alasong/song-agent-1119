# ASI 方案 v2：四层 + 独立性记账

> 状态：**设计草案 v2**。取代 v1（`docs/ASI-方案-v1.md`）的定位：v1 是「可验证域的基础设施规格」，v2 补上生成层、记忆粒度、独立性记账与不可判域处置。
> 结论未获证据支持：P2 的 go/no-go 一次都没跑（§9）。
> 外部参照：KAA（`fat3/skills/kaa/`）、L3M（arXiv 2610.19591）。

## 0. 一句话定界

**超智的稀缺资源是「真实且便宜的判定」；大规模 agent 是这个判定需求的产物，不是原因。**

数量由「独立性」买单：同模型、同提示、同证据的一千个 agent，等于一个 agent 的一千份复印件。

## 1. 四层

| 层 | 干什么 | 缺了会怎样 | v1 的状态 |
|---|---|---|---|
| 生成层 | 候选从哪来：多视角、跨域类比、变异、反向出题 | 只会在已有假设里转，不产生「想不到的」 | 完全没有 |
| 判定层 | 可执行谓词集 + 对抗集自举 + 判据版本化 | 判据假，规模越大错得越快 | 有骨架、无自举算法 |
| 选择层 | 通过 / 成本 / 不确定性三元淘汰，去重与聚合 | 成本全花在重复项上，慢热路线被误杀 | 只按通过率与成本 |
| 记忆层 | 技能库（可执行工具）、判据库（版本化）、失败样本库 | 短命 agent 每次重新发明，经验不累积 | 只说「资产」，无粒度 |

## 2. 核心对象：WorkNode

```
WorkNode = (目标, 判据谓词集, 判据等级, 预算, 深度)
```

状态机：`立项 → 分解 → 执行 → 判 → 固化 | 淘汰`；失败样本一律回流到判定层与记忆层。

两条硬规则，这次都做成可机检：

1. **判据冻结**：判据写进账本，执行期不可改；改判据 = 新建节点。落点 `sa2/core/harness.py#register`。
2. **分解不稀释**：父判据是**谓词集 P**，子节点判据必须是 **P ∪ Q 的超集**；包含关系由机器判，不靠文字比对。做不到谓词化判据的域，不许进节点，只能降级为 L3 建议。

## 3. 判据等级

| 等级 | 是什么 | 用法 |
|---|---|---|
| L0 | 形式真值（编译器、内核、测试 rc） | 直接判 |
| L1 | 可复现测量（实验、对账） | 多次取一致 |
| L2 | 人类标注 | 只校准 L0/L1 的边界 |
| L3 | 模型判断 | **只提议，不计分，不单独判** |

规则：完成必须有 ≥L1 判据；判据等级是节点必填字段，缺则立项即拒。

## 4. agent 计数与独立性记账

| 来源 | 数量公式 | 例：100 节点 · M=16 · k=2 | 独立性来源 |
|---|---|---|---|
| 候选生成 | 节点 × M | 1,600 | 不同视角、类比源、起点 |
| 独立判定 | 幸存候选 × k | 160 × 2 = 320 | 不同证据路径、不同工具、不参与生成 |
| 深挖 | 幸存候选 × 1 | 160 | 各带一条失败反馈 |
| 对抗矿工 | 预算的 5% | ~50 | 目标与生成方相反 |
| 资产固化 | 少量 | ~20 | 把成功路径写成工具 |

**合计约 2,150 agent/轮**（设计初值，未实测）；峰值并发 300–500，由判定吞吐与预算共同限流。

**独立性认证（I4）**：一个 agent 必须至少满足一条才算独立单位——不同证据来源 / 不同工具 / 不同判据 / 不参与生成。不满足的计数一律压缩，不进入并行度统计。

**瓶颈顺序**（限流按此排序）：判定吞吐 → 资产检索 → 合并去重 → 成本。大规模系统的工程重点是压缩与聚合，不是 spawn。

## 5. 判据自举（P2 的算法，v1 缺的那一块）

一圈五步，全部可机检：

1. **挖反例**：在 held-out 上找假阳性（判据说对、实际错）与假阴性；
2. **聚类**：按失败模式归并，得到「判据哪一类问题看不见」；
3. **谓词化**：把每类失败写成一个可执行谓词（代码），不是一条文字规则；
4. **双向验收**：老样本不许误杀（回归）+ 新对抗集必须多抓（增益），两个都要过；
5. **入库**：判据带版本号、来源样本 id、生效时间，写进判据库。

**对抗集自举**：拿已知错误答案反向喂判据；优先标注「判据摇摆」的输入——它自己拿不准的地方就是它最弱的地方。

## 6. 读数（防 Goodhart）

| 读数 | 现状 | 量法 | 要求 |
|---|---|---|---|
| 判据抓错率 | 16.7%（24 条对抗件过 4 条） | 对抗集假阳性率 | 单调上升，P2 目标 ≥60% |
| 联合效率 | 无此读数 | 通过率 @ 固定成本（带区间） | 单位成功成本单调下降 |
| 剪枝率 | 无此读数 | 每正确解花掉的搜索节点数 | 单调下降 |
| 资产复用率 | PlanStore 有、无曲线 | 用上已验证资产的节点占比 | 单调上升 |
| 人工介入率 | 依赖 daemon | 从立项到完成找人次数 | 单调下降 |

只认联合量，单指标（尤其「每正确解搜索节点数」）可被拆细问题或早停作弊。

## 7. 预算按不确定性分，不按当下读数分

冷启动阶段正确方向的通过率也低，纯按读数淘汰会误杀慢热路线。规则：不确定性高的路线给**保底预算**，读数只决定增量；保底预算的来源是资源账本里单独的一档。

## 8. 不可判域的三档处置

| 档 | 场景 | 谁定盘 | 读数 |
|---|---|---|---|
| A | 判据人给、机器执行 | 人给判据 | 人工介入率、执行成本 |
| B | 机器提议、人抽样校验 | 模型提议 + 人抽检 | 抽检命中率、误放行率 |
| C | 纯探索预算 | 无人定盘，只记账 | 探索产出 / 预算 |

不可判域只能靠这三档，不能假装可判——这是本方案对「通用超智」最诚实的边界。

## 9. 建成顺序

| 步 | 建成什么 | 读数 | 判红条件 |
|---|---|---|---|
| P0 | 一个 L0 域 + verifier + 对抗集 + 任务生成器 | 抓错率 | 对抗集建不起来 = 停 |
| P1 | 生成层 + 搜索环（多路深挖、先验复用、去重聚合） | 剪枝率、联合效率 | 不比单路好 = 回退 |
| **P2（go/no-go）** | 判据自举 + 对抗集自举 | 抓错率上升、held-out 不降 | **不涨 = 方案作废，退化为高级执行器** |
| P3 | 淘汰层 + 不确定性预算 | 单位成本下降 | 成本不降 = 回退 |
| P4 | 跨域：换验证器不换骨架 | 新域达标轮数 | 轮数不降 = 骨架不通用 |
| P5 | 按可逆性退出人审 | 人工介入率 | 不降 = 未退出 |

## 10. 与 v1 / KAA / SA / L3M 的差别

- 对 v1：补生成层、独立性记账、判据自举算法、对抗集自举、联合读数、不确定性预算、不可判域三档。
- 对 KAA：它给判定层的工程形态（出厂 spec、`derive --check`、判定谓词不可自改）；本方案在它之上加「判据自己变强」这一层——那是 KAA 没有的。
- 对 SA 2.0：给不死与资源；但角色制降级为「临时执行者」，长期对象只有节点与资产。
- 对 L3M：接「人不能在每个回路里」与可逆性分级（P5）。

## 11. 未定项

- 判据自举的谓词化步骤在真实域上的增益未测；
- 2,150 agent/轮 的并发与去重没有实测，可能远低于预期；
- 不可判域的 B 档（模型提议 + 人抽样）如何定义「抽样够不够」尚无判据；
- L2 校准集仍不存在。
