# ASI 方案 v1：判据驱动的深度递归搜索机

> 状态：**设计草案**。未获准全量实施；P2 是 go/no-go 门（§8）。
> 来源：2026-11-20 会话的论证链，不是凭空提案。参照物：KAA（`fat3/skills/kaa/`，递归 PDCA 执行树第三代实现）、L3M（arXiv 2610.19591）。
> 与 SA 2.0 的关系：**共用同一具骨架**，改五处（§6）。不新开仓库。

## 0. 一句话定界

**超智的稀缺资源是「真实且便宜的判定」，不是并行宽度、不是组织架构、不是流程完备。**

本方案把判定做成机器的核心资产，让判据自己变强；其余全是配套。配套再好，替代不了这一件。

## 1. 目标与非目标

**目标**：在可验证域上做到「每正确解花掉的搜索节点数比人类少一个数量级」，并把这条曲线持续压下去；同时做到不需要人出判据、不需要人发现错误。

**非目标**：

- 不做长期角色、编制、汇报链——那是给「人的带宽与信任有限」设计的，AI 没这两个约束；
- 不让模型给自己判卷（L3 只能当提议，§4）；
- 不靠增加并行度换能力——宽度是判据不足时的兜底，不是能力来源。

## 2. 核心对象：WorkNode

系统里唯一的长期对象是节点：

```
WorkNode = (目标, 判据等级, 判据, 预算, 深度)
```

状态机：

```
立项 → 分解 → 执行 → 判 → 固化 | 淘汰
                      ↘ 失败样本 → 进化环（§3）
```

两条硬规则：

1. **判据冻结**：节点创建时判据写进账本，执行期间不可改。要改判据 = 新建节点，旧节点作废并留痕。这条把 KAA 的 A6「判定谓词不可自改」从公理变成物理事实。
2. **分解不稀释**：子节点必须继承父节点的必要条件；「把大目标拆小」不能变成「把标准调松」，一旦放宽，判定即红。

**agent 不是长期对象**：节点需要执行者，就临时创建一个，用完即弃。因此没有角色档案、没有编制、没有接管链——「不依赖单个 Agent 生死」由节点与账本承担，不需要角色制。

## 3. 三种回路

| 回路 | 时间尺度 | 做什么 | 谁判 | 与上一层的关系 |
|---|---|---|---|---|
| 执行环 | 秒–分钟 | 单节点内 生成 → 自检 → 重试 | L0/L1 判据 | 被搜索环调用 |
| 搜索环 | 分钟–小时 | 同一节点多路**深挖**、交叉验证、选优 | 同一判据 + 预算淘汰 | 调用执行环；受进化环改进 |
| 进化环 | 天–周 | 从失败样本挖新判据；成功路径固化成资产 | held-out 集（防过拟合） | 改进上面两层的判据与先验 |

**「环环嵌套」的正确实现**：第 n 层节点的判据，是第 n+1 层的目标；第 n+1 层用更底层的真值判它。判据的判据永远落在**真值**（内核 / 测试 / 可复现实验）上，不落在「更强的模型判断」上——所以不会无限回退。

## 4. 判据等级

| 等级 | 是什么 | 谁产生 | 允许的用法 |
|---|---|---|---|
| L0 | 形式真值：编译器、Lean 内核、测试 rc | 工具 | 直接判 |
| L1 | 可复现测量：跑实验、对账、复现 | 工具 + 记录 | 多次取一致 |
| L2 | 人类标注 | 人 | 只校准 L0/L1 的边界 |
| L3 | 模型判断 | 模型 | **只提议，不计分，不单独判** |

三条使用规则：

1. 任何节点的「完成」必须有 **≥L1** 的判据；
2. L3 只能用来建议往哪里搜索（剪枝方向），不能进判定；
3. 判据等级是节点的必填字段，缺字段 = 立项即拒。

## 5. 三条不变量与机检落点

| # | 不变量 | 判红方式 | 现有落点 |
|---|---|---|---|
| I1 | 生成方不持有判据 | 执行期间改判据 = 拒绝迁移 | `sa2/core/harness.py` 的 `register` 冻结判据（已有） |
| I2 | 无 ≥L1 判据不许完成 | `checked → done` 边要求校验命令 rc=0 | `sa2/core/harness.py` 的 `EDGES`（已有雏形） |
| I3 | 状态只能从 append-only 事件重放 | 任何内存态不作为真相 | `sa2/core/ledger.py`（已有） |

## 6. 与现 SA 的五处差别

| 现在的 SA | 本方案 | 性质差 | 代码归属 |
|---|---|---|---|
| 长期对象是**角色**（档案/承诺/接管） | 长期对象是**节点**，agent 用完即弃 | 组织图消失，只剩节点树 + 资产库 | `sa2/memory/profiles.py` → 收缩为临时执行者记录 |
| 四个循环并存、互不知道 | 三个回路是同一节点的**嵌套** | 从多套壳变成一层套一层 | `sa2/loop/pdca.py`→执行环；`dev.py`→执行环；`outer.py`→进化环；`compare.py`→搜索环选择器 |
| 门按**任务类型**分层（annotation/engineering） | 判据按**等级**分层（L0–L3） | 从「过不过」变成「凭什么判、允许多弱」 | `sa2/core/gate_profiles.py` → 并入判据等级 |
| 完成 = 门过了 | 完成 = 有 ≥L1 判据且判据冻结 | 判定权从流程里挪到节点外 | `sa2/core/harness.py` 扩展 |
| 采纳 = 打分选优，预算只记账 | 淘汰 = 杀路线 + 资产继承 + 无进展削预算 | 从「选好的」变成「让差的死掉」 | `sa2/loop/outer.py` + `sa2/core/resources.py` 加分档削减 |

## 7. 增长公式与四条读数

**能力增速 = 判据抓错率提升 × 复用率提升 × 搜索效率提升**

| 读数 | 现状 | 怎么量 | 要求 |
|---|---|---|---|
| 判据抓错率 | 16.7%（24 条对抗件过 4 条） | 对抗集上的假阳性率 | 单调上升，P2 目标 ≥60% |
| 资产复用率 | 有 PlanStore，无曲线 | 用上已验证计划的节点占比 | 单调上升 |
| 搜索效率（剪枝率） | 无此读数 | 每正确解花掉的搜索节点数 | 单调下降 |
| 无人介入最长步数 | 依赖 daemon 队列 | 从立项到完成不找人 | 单调上升 |

后三条里，**剪枝率是新读数**，也是唯一能区分「变聪明」与「变能烧钱」的量。

## 8. 建成顺序

| 步 | 建成什么 | 读数 | 判红条件 |
|---|---|---|---|
| P0 | 选一个 L0 域，建 verifier + 对抗集 + 任务生成器 | 抓错率 | 对抗集建不起来 = 停 |
| P1 | 搜索环：多路深挖 + 先验复用 + 预算淘汰 | 每正确解搜索节点数 | 不比单路好 = 回退 |
| **P2（go/no-go）** | 进化环：失败样本自动产出新判据，held-out 不降 | 抓错率上升 | **不涨 = 整套退化成高级执行器，方案作废** |
| P3 | 淘汰层：多路线并行，只留通过率与成本都胜出的那条，资产由胜者继承 | 单位成本下降 | 成本不降 = 回退 |
| P4 | 跨域：换验证器不换骨架 | 新域达标轮数 | 轮数不降 = 骨架不通用 |
| P5 | 退出：按可逆性分级，不可逆才找人审 | 人工介入率 | 介入率不降 = 未退出 |

P2 是唯一的否决门：判据不能自己变强，本方案与前几版没有本质差别。

## 9. 与三个先例的关系

- **KAA**：给判定层的工程形态（出厂 spec、三层解耦、`derive --check` 十项静态检查、判定谓词不可自改）。它不产生判据，是防错系统，不是发现系统。
- **SA 2.0**：给不死与资源（账本、租约、池、预算、接管），是本方案的传动与底盘。
- **L3M**：给「人不能在每个回路里」这条规模前提，以及可逆性决定自主档的做法。

## 10. 未定项

- 判据自动生成的算法未定：从失败样本挖规则的具体形式（聚类反例 / 生成谓词 / 人审抽样）尚无实现与读数；
- L2 校准集不存在：当前没有任何一份人类标注集，所以「判得准」这件事一直无法校准；
- 跨域迁移未验证：同一骨架换验证器是否真的通用，只有设计意图，没有读数。
