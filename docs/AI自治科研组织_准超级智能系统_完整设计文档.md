## 一、核心命题

不是造一个聪明的单体Agent，而是造一套"能自己长出组织架构、能自我检测腐烂、能自我重构、任何单点故障不致死"的活性组织系统。

人类角色 = 董事会：只提目标、定红线、审批结构性变更。不介入日常执行。

---

## 二、核心DNA（8条，硬编码，不可运行时篡改）

| # | DNA | 含义 | 落地形式 |
|---|---|---|---|
| 1 | 目标锚定 | 一切围绕顶层目标转 | 目标树 + 偏离度计算 |
| 2 | 可度量 | 每个层级有量化健康指标 | 5个核心指标持续采集 |
| 3 | 可编排 | 所有组件可插拔、可组合、可替换 | 编排引擎动态创建/销毁角色 |
| 4 | 可观测 | 全链路可追溯 | 审计日志服务 |
| 5 | 可回滚 | 任何变更有版本、可灰度、可回滚 | 发布管理服务 |
| 6 | 自演化 | 上层评估下层健康度，自动提出调整 | 自迭代引擎 |
| 7 | 腐烂检测+重构决策 | 差距小→局部调优，差距大→推倒重构 | 健康指标+阈值判断 |
| 8 | 激励对齐 | 每个角色的收益与顶层目标同向；验证者的收益来自抓错，与生成者相反 | 预算账户+收益账本 |

## 三、递归层级结构

```
L(-1): 人类董事会
  │  设定目标、红线、审批结构性变更
  ▼
L0: 执行层（动态Agent团队）
  │  根据目标动态创建/销毁角色
  │  执行：调研→推导→实验→验证
  ▼
L1: 治理网络（多节点共识，无单点故障）
  │  采集L0健康指标
  │  发现腐烂 → 决策：局部调优 or 结构性重构
  │  执行灰度 → 对比效果 → 回滚或固化
  │  节点互相监控，任何节点有热备
  ▼
L2+: 元治理层（远期）
    监控L1自身效果，决定L1策略是否需重构
```

关键原则：
- L0和L1不写死耦合，预留递归扩展
- 去中心化：任何节点挂了→热备接管；整个实例摧毁→从DNA重新启动
- 7条DNA是"宪法"，任何角色的任何决策不能违反

## 四、L1健康指标（5个核心）

| 指标 | 采集方式 | 异常信号 | 触发动作 |
|---|---|---|---|
| 目标偏离度 | 当前任务与顶层目标语义相似度 | 持续上升 | 暂停，重新规划 |
| 校验通过率 | Verifier通过数/总提交数 | 持续下降 | 加强校验或调角色 |
| 通信效率 | 有效工单/总消息数 | 下降 | 收紧沟通预算 |
| 资源利用率 | 有效产出/Token消耗 | 下降 | 终止低效率路径 |
| 假设证伪率 | 被推翻假设/总假设数 | 异常高 | 回溯更早前提 |

## 五、Agent角色模板（6种，MVP用）

| 角色 | 职责 | 约束 |
|---|---|---|
| Planner | 目标拆解、里程碑定义 | 只做规划，不参与执行 |
| Researcher | 文献检索、事实提取 | 区分事实与推论 |
| Expert | 领域推导、方案设计 | 依赖共享知识底座 |
| Executor | 代码、仿真、实验 | 只执行，不评判 |
| Verifier | 独立校验（永久隔离） | 不读取生成方思维链 |
| Curator | 知识归档 | 只存已验证事实 |

## 八、强制底线规则（MVP不可删减）

1. 所有通信仅结构化工单
2. Verifier永久隔离
3. 所有产出附带证据链
4. 知识底座只存已验证事实
5. 完整审计日志
6. 基础熔断（步数/Token/时长）
7. 所有结构性变更走灰度+版本化+回滚
8. 收益账本公开可审，越级告警不得被 L1 拦截（v2.1）

## 十三、自举协议（Bootstrap Protocol）

输入：算力 + 基础模型 + 7条DNA
输出：一个能自我组建、自我监控、自我重构、自我修复的活性组织

启动流程：
1. 加载DNA（硬编码校验）
2. 初始化治理网络（至少2节点+热备）
3. 接收人类目标
4. 编排引擎创建L0团队
5. 开始执行+监控循环
6. 任何故障→自动恢复→从断点继续

## 十五、激励层（L0.5）：这套设计原先缺的那个维度

> v2.1 新增。前 7 条 DNA 全部是「不腐坏」，没有一条产生「多做一步」的动机。
> 人类组织强于个体之和，不是因为职能齐全，而是因为有**压力结构**：做得差会失去资源，
> 做得好会拿到更多资源，藏错会被举报，挑错有声誉收益。
> 抄职能不抄压力，得到的是六个会写工作日志的 agent。
>
> AI 相对人类组织多三个杠杆：并行度不受人头限制、经验不遗忘不离职、上下文可选择性共享。
> 这三个杠杆只放大吞吐，不自动提升正确性——所以下面每一条压力机制都是必需的，不是可选的。

### 15.1 利益驱动三件套

| 机制 | 人的原型 | 工程落地 |
|---|---|---|
| 预算账户 | 部门预算、HC 编制 | 每个角色/团队持有 token+步数预算；达标上浮，无进展衰减，连续 N 轮衰减→角色销毁 |
| 收益函数 | KPI、奖金、晋升 | 生成方收益=目标推进量；**验证方收益=抓到的真错 − 漏放的错**。原 §4 把「校验通过率下降」当异常，等于奖励盖章、惩罚挑错，须反向：通过率异常**高**才是异常信号 |
| 赛马竞争 | 内部竞标、立项赛马 | 同一子目标允许 ≥2 队并行；赢家方案进知识底座，输家预算减半但不销毁（多样性不能清零） |

### 15.2 主动性：人为什么主动，AI 就装什么

人主动不是靠觉悟，是四样东西同时在位。四样必须一一对应，缺一件就退化成「派了活才动」：

| 人的机制 | 设计里的承载体 |
|---|---|
| 目标感（这事归我） | **常驻目标**：agent 启动即持有目标树的一个子树，空闲时巡检自己的子树，不等派活 |
| 怕掉队（KPI 压力） | **心跳+无进展检测**：子树 N 小时无新事实入账，自动产出「在做什么/卡在哪/下一步」自述单；连续两轮无进展→上交 L1，由 L1 决定换人或换向 |
| 想做好（自我要求） | **分阶段自评 gate**：每阶段结束必须先自答四问（目标是否在候选集内最优、过程是否更优、有无漂移、结果是否达标），答案入库留痕 |
| 不确定就问（找人商量） | **不确定性触发求助**：置信度低于阈值强制发起评审/检索，不许硬写；问的成本计入预算，但「没问导致返工」双倍计入——让「问」比「瞎猜」便宜 |

### 15.3 自评必须被校准，否则是自嗨

人做完项目要复盘，复盘的价值在于**下一次判断更准**，不在于写总结。落地：

- 每阶段自评存为 `self_review(stage, 四问答案, 置信度)`；
- 阶段结束与最终结果比对，算 **calibration score**（自评置信度与实际达标的偏差）；
- 长期自评虚高的角色，后续自评权重下调，其「我认为可以」不再作为准出依据。

### 15.4 各阶段都要做到最好，不能只在最后验收

> 原例：软件不是只有最后的测试验收要好，需求分解、设计、架构、开发效率、定位效率、运维效率、质量每个阶段都要做到最好，才谈得上稳定、好运维、好扩展。

因此每阶段设**准出项（stage gate）**，准出项必须可机检，不合格不许进下一阶段：

| 阶段 | 准出项 |
|---|---|
| 需求分解 | 每个子目标有可执行判据/验收命令；无判据的子目标不计入进度 |
| 设计 | 接口契约存在，且被下游角色签收 |
| 实现 | 判据跑过（测试/仿真/证明）；修复类任务先有红用例再转绿 |
| 定位 | 有最小可复现用例；修完该用例必须转绿 |
| 运维 | 回滚演练通过；指标连续上报 N 天无断档 |

阶段失败计入该角色收益账本——这就是「绩效」，也是主动性可持续的来源。

### 15.5 承载体契约：治「名词当机制」

原 §十二 的 38 条里，多个承载体只是名字（`#30 基础设施腐烂｜递归腐烂检测｜递归腐烂检测`，问题、方案、承载体是同一个词）。补法：

每个承载体必须有一份 **Contract**，四要素缺一不可：**输入 / 输出 / 失败信号 / 拒收规则**。
下游拥有**拒收权**：产出不合格直接打回，打回记入上游收益账本（人类叫「这活被打回重做」）。
38 条逐条补 Contract，补不出的标 `TODO`，并在 MVP 边界里降级为「未实现」——不许留在表里充数。

### 15.6 异议与越级：治「董事会只是盖章」

| 人类制度 | 对应机制 |
|---|---|
| 董事会否决权 | 人类只审三样：偏离度曲线、被驳回告警数、抽样审计结果；看不懂即否决，否决成本为零 |
| 独立审计、外部董事 | 审计 Agent 独立于 L1，直接向人类出报告 |
| 举报通道、吹哨人 | 高风险动作**越级告警**：不经 L1，直入人类告警队列；举报被证实有收益 |
| 罢免 | 人类可单点销毁任意角色/节点，不需理由 |
| 法律高于公司 | DNA 放在系统写不到的信任根：摘要签名+启动验签+结构性自改须人类私钥。否则「硬编码」只是没写测试的承诺 |

### 15.7 不死 = 可重建，且必须带状态

自举输入不能只有「算力+基础模型+DNA」。DNA 之外必须持久化并纳入恢复演练：

- 知识底座快照（Merkle 根登记进 DNA）
- 案例库（失败经验，人类叫「事故复盘库」）
- 断点状态与收益账本
- **恢复演练是验收项**：不定时真实演练「杀掉实例→重建→继续」，演练不过视为不具备可用性

### 15.8 可失去性与自我档案：动力从哪来

> 补 §15.1 没落地的两块。§15.1 只给了预算账户与收益函数，销毁权仍捏在 L1 手里，那是**外部惩罚**，不是「失去」；
> 而「自我价值」在 agent 这边压根没有承载体，跨会话一失忆，就谈不上「我要成为什么」。

**（1）可失去性自动化：不设「谁来决定销毁」，让账本自己执行**

- 账本连续 N 轮无有效产出 → 自动降级：预算减半，角色转只读
- 再连续 N 轮 → 自动关停，不设人工审批路径
- 关停不是删除，是**冻结**：档案留在案卷库，可被重新唤醒（人类叫「待岗」，不是「开除」）
- 降级/冻结记录必须对下游可见；**不可见的惩罚等于没有惩罚**

**（2）自我档案（self-model）：让「我是谁」有落点**

每个角色持久化一份档案，跨会话不丢：

| 字段 | 内容 | 用途 |
|---|---|---|
| 战绩 | 已完成 / 被打回 / 被驳回次数 | 声誉，也是预算升降的依据 |
| calibration | 自评置信度与实际达标的偏差 | 自评权重；虚高者降权 |
| 专长与短板 | 领域标签 + 历史失误模式 | 派活路由，避免重复踩同一个坑 |
| 未偿承诺 | 承诺过但没做完的事 | 新会话第一件事就是接管它们 |
| criteria_version | 该角色当前采用的判据版本 | 见（3） |

**（3）判据版本：标准是各人自己装的，那就在系统里把版本显式化**

人的自我标准是内化的外部评价，各人装的版本不同。这在 AI 组织里必须显式化，否则两头都会坏：判据全同 → 集体盲区；判据互不兼容 → 无法比较、无法校准。

- 判据存进**判据注册表（Criteria Registry）**，每条带版本号；
- 角色可以提出新判据版本，但**必须过 calibration 才能升格为默认**：新判据下自评准确率不劣于旧版，且至少多抓到一条旧版漏掉的错误；
- 档案记 criteria_version，复盘时才能分清「是判断错了，还是判据本身不对」。

这三样合起来才是「利益驱动 + 自我价值驱动」在 agent 侧的对应物：前者给**可失去性**，后者给**连续的自我与自设标准**。只有惩罚没有自设标准，训出的是会规避风险、隐瞒错误、刷通过率的应试机器。

### 15.9 与原设计的关系

不推翻原设计。原设计解决「组织不腐坏」，这一层解决「组织有动机、有主动性、有压力」。
缺这一层，前 14 章是一台无人值守但不会主动加班的机器；加上这一层，才是「活性组织」。
