## 0. 一句话

让「目标达成」成为组织的不变量：实例会死、组织不死；资产会积、下次不重走；组织能改自己，
最终超过人类组织。**B（常驻池 + 热备）是终点；A（档案 + supervisor + 接管）是 B 的载荷与试验台。**

## 1. 三条不变量（每条一个可判红动作）

| # | 不变量 | 可判红动作 |
|---|---|---|
| I1 | 目标守恒 | 杀掉任一 agent，任务仍完成；账本有 `role_died` + `takeover`，接管包带未偿承诺与已完成部分 |
| I2 | 能力累积 | 同类任务第二次，编制/判据/工具至少一项零重建 |
| I3 | 对超可判 | 同预算双臂可复跑；候选集/预算/判据版本/差值四件不全，不许称「更优」 |

## 2. 为什么先 A 后 B（A 是 B 的载荷）

公司里 CEO 死了，副总接的是三样东西：**目标与当前进度、预算与授权、未偿承诺**。
这三样在现在的代码里都没有承载体：`Role` 只有 name/kind/duty/criteria/budget/tools
（`sa2/forge/org.py:26-34`）；预算是一次性构造的数；没有任何字段记「承诺过还没做完的事」。

B 只保证「进程还在」。先 B 后 A，得到的是一群互相盯着的、没有记忆的进程：
死一个，另一个从零开始——**那叫重启，不叫接管**，而且读数是绿的（进程数、心跳都正常），
骗得比红还狠。

所以顺序是 A → B，但**接口必须按 B 的形状定死**，A 只是「一个 worker 的池」；
B = 换载体（多进程 + 租约 + 心跳），PDCA 环与判定层不动。

## 3. 接口契约

派活不是一个函数调用，是一条持久记录。四个契约：

| 契约 | 字段 | 为什么 |
|---|---|---|
| `Dispatch` | id / role_id / stage / duty / **criteria 快照** / input_ref / budget / deadline / attempt / lease_id | 派活是记录，进程死了记录还在；自带 criteria，PDCA 不必回查 frozen 的 OrgPlan |
| `Lease` | dispatch_id / worker_id / expires_at / heartbeat_at | 谁在干、干到什么时候；过期即可被抢，不靠「发现」 |
| `Handover` | role_id / 未偿承诺 / 已完成部分摘要 / 上次失败原因 / 上游 / 剩余预算 | 接管接的是这三样，不是一句「你继续」 |
| `RoleProfile` | id / kind / duty / tools / 战绩 / calibration / **专长与短板** / 未偿承诺 / criteria_version / status | §15.8 的五项档案；没有身份，死亡就没有承载体 |

`Supervisor` 的职责只有一条：**把每次死亡变成一次可重派事件**。
异常、超时、租约过期 → 账本 `role_died` → 同 kind 的同伴接 → 没有同伴就克隆档案当继任
→ 仍未成立进领导队列。每次接管写 `takeover`（from / to / handover 摘要 / 从哪继续）。

## 4. 数据契约

- **真源是账本事件，不是队列状态**（`sa2/core/ledger.py:1-4`：事件流是唯一真相，状态是投影）。
  `DispatchQueue` 是投影/缓存，租约抢占 = 追加 `lease_expired` / `takeover` 事件后重放，不做双写。
- `RoleStore`：JSONL，一行一个档案；按 id 取，按 kind 查同伴。
- `state.json`：从阶段级改**角色级**（本阶段哪些角色已完成、输出在哪）。
- 账本事件：`dispatch`（载荷扩为 id/role_id/lease_id）/ `role_died` / `takeover` / `lease_expired` / `stage_ok` / `reject`。

**死的单位是角色，干活的单位是 worker。** 一个 worker 是可替换的工位，一个角色是有档案的人；
kill 掉 worker，在飞的 dispatch 丢租约、重派给同一个 role_id（同一份档案，代次 +1），
账本记 `dispatch_lost` + `role_died`（若角色本身没做完）+ `takeover`。

## 5. 分期与验收（按依赖排，不按难度排）

| 期 | 做什么 | 验收命令（可判 0/1） |
|---|---|---|
| P0 | A 内核：RoleProfile/RoleStore、Dispatch、Supervisor、角色级 checkpoint | `python3 -m unittest tests.test_sa2_liveness -q`；drill 杀掉一个角色后 `passed=True` 且账本含 `takeover` |
| P1 | B 载体：多 worker 进程 + 租约 + 心跳 | `scripts/drill_kill.py --kill-worker`：kill -9 一个 worker，在飞 dispatch 租约到期被重派，任务完成，账本跨进程 `takeover` |
| P2 | 资产复用：PlanRegistry（**复合键**：goal + budget_cap + criteria + tools + headings） | 同条件第二次 `plan_org` 调用 0 次、tokens 下降、账本 `plan_reused` |
| P3 | 对超可判：`ab_org.py` 双臂（组织 vs 单人基线）+ 盲评 + Pareto | 产出双臂读数与 L0/L1/L2 判定；缺四件时拒绝称「更优」 |
| P4 | 健康指标 + 外环（探索新因素） | 指标可从历史 run 复算；外环一条候选实验（预算上限 + 采纳/拒绝落盘） |
| P5 | 资源账本（钱/额度 + 采购审批） | 超阈值进领导队列且不能继续；池不可超支 |

P0 里 `Supervisor` 是唯一新增的调度面；P1 只换 worker 的实现，不改 PDCA。
P4 与 P5 现在不做：外环没有指标就是瞎探，购买没有账本就没有闸。

## 6. 非目标

- 不做多机分布式共识、不做真钱支付（P5 只做账本 + 审批）。
- 不动判定权：生成方永不对判据拥有判定权（`Judge.authority` 不变）。
- 不把「常驻」理解成「永不退出」：角色可以冻结、可以被唤醒，冻结不是删除（§15.8）。

## 7. 风险与止损

| 风险 | 止损 |
|---|---|
| 租约/心跳做重，重演 1.0 的 38 次调用 | 先在单进程用假时钟把红测出来，再上真进程 |
| 接管包太大把上下文打爆 | 只带未偿承诺 + 已完成部分摘要 + 失败原因 + 剩余预算 |
| 判据看不见「整段重做」这种失败 | 账本断言：单一阶段 dispatch 次数 ≤ 3 × 角色数（含交付门回退那一次 attempt=2，见 `pdca.py:162-166`） |
| 演练脚本本身造假（假模型全绿） | 演练必须假模型（确定性）+ 真模型（`--live`）各跑一次 |

## 9. 留给 builder 的决定

- worker 用进程还是线程（P0 线程即可，P1 进程）。
- 租约时长与心跳间隔的具体数值（先用假时钟定红，再按真跑读数调）。
- `Handover` 的「已完成部分摘要」由模型写还是由系统裁（建议系统裁，模型写会注水）。

## 10. 已自决的分叉（builder 审出的前三问）

- **G1 身份与载体分离**：死的是角色（有档案、有未偿承诺），worker 是工位。这样 B 的进程池
  可以任意替换 worker，而「谁死了、谁接了他的承诺」始终可读。
- **G2 账本是唯一真源**：队列只做投影，租约抢占走「追加事件 + 重放」，避免双写对账。
- **G3 继任用同一 role_id + 代次**：档案换代而非新身份；`Dispatch` 自带 duty/criteria 快照，
  PDCA 不回查 frozen 的 `OrgPlan`。

## 11. 决策规则（按目标判，不按人判）

领导握**判定权**（目标、红线、否决、越级告警）；**判断权**（怎么做、先做哪个）在组织。
分叉按顺序过三条不变量，会削弱其中任一条的选项不做：

1. **目标守恒**：这个选择会让「杀一个角色、任务仍完成」变弱吗？
2. **能力累积**：会让同类任务多一次重建/重做吗？
3. **对超可判**：会让读数变得不可复跑、不可比吗？

判不出时，选**可逆且便宜**的那个先做（最小代价实验），结果记账本；仍判不出才升级领导，
且只带：两个候选、各自代价、推荐哪个、为什么——不带开放问题。

这条规则也是运行期要求：P4 的外环探索、P5 的采购审批走同一条，不许写成「等领导批」。
（人机判断的差别不在「能不能判」，在判错的代价谁承担——所以留的是否决与越级告警，不是审批。）

### 11.1 已按此规则判掉的分叉

- **calibration 是否在 P0 给真值** → 空壳。
  不影响 I1（接管靠未偿承诺与已完成部分，不靠自评）；不影响 I2（空壳不阻碍复用）；
  不影响 I3（自评这一层都还不存在）。真值是 P4 的事。
  P0 必须真值的只有三项：**战绩、未偿承诺、专长与短板**——接管与路由要用。
