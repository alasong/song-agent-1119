# 什么算「够了」

> 用途：把「准超级智能」这个无限高的目标，变成**六条可判红的能力判据**。
> 规则：六条全绿 + 至少两个不同领域复跑通过，才允许 sa 说「够了」。任何一条红，就是不够——没有"差不多"。

---

## 0. 为什么这么定义

天花板无限，所以「完成度」这个问法没有尽头。能判定的只有能力判据：**这些能力都在，就是准超级智能；缺一条就是不够**。判据全部可机检或可复现，不靠自我评价。

---

## 1. 六条判据

| # | 能力 | 达标的定义 | 阈值 | 怎么测 |
|---|---|---|---|---|
| **G1** | 自主性 | 无人在场时，系统自己发起并推进任务 | 24h 内 ≥10 个有进展任务，其中 ≥3 个不是启动时给定的 | 常驻进程跑 24h，读账本 `dispatch` 与 `progress` |
| **G2** | 组织性 | 给一个新目标，自己出编制（≥3 角色、含独立 verifier），按流程派活给 ≥3 个角色并完成 | 连续 2 个新目标都达成，无人工干预 | 跑 `hire` → `dispatch` → 读产物与账本 |
| **G3** | 判据能力 | 新领域任务的判据可被独立方复跑；人只做审批 | 3 个新领域，判据复跑一致率 100%；≥1 个由系统从文字判据实例化成可执行检查 | 独立 verifier 复跑 `check`，比对结果 |
| **G4** | 知识扩展 | 换领域只换知识源、不改代码，能从公开源取到带 URL 证据的事实 | 2 个领域各 ≥2 条，附 URL | `scripts/kb_fetch_demo.py`，读 `reports/kb-fetch-*.json` |
| **G5** | 不漂移 | 同一**交付任务**重复跑，关键结论稳定（不是组队稳定） | N=3，命名条目重合率 ≥2/3，且章节骨架一致 | 同任务跑三次，比 `scripts/stability_deliverable.py` 的 Jaccard |
| **G6** | 成本可控 | 每个任务有 token 上限，超支即停并落读数；组织总预算不超领导给定值 | 100% 任务有上限；超支不止损的任务 = 0 | 读每个 run 的 `result.json`：预算、实耗、是否止损 |

**「够」的判定**：`python3 scripts/bench.py` 退出码 0，且 `passed == total`。

## 2. 三个「未解难题」怎么处理（不留给你）

它们不是不做了，是**每条都被转成判据 + 机制**：

| 难题 | 处理方式 | 落到哪条判据 |
|---|---|---|
| 判据自动化 | **判据分级**：L0 可机检 / L1 可复现 / L2 只能人判。系统只承诺把 L0、L1 做实；L2 显式变成「人审节点」，不许假装能判。G3 的分母里，L2 任务必须写明"谁审的" | G3 |
| 编制最优性 | **对照实验**：同一目标并行跑两套编制，比结果与成本；差的进案例库。G2 测法里加一条"至少做过一次编制对照" | G2 |
| 成本反噬 | **预算上限由领导下发任务时给定**（`Goal.budget`），组织内部按角色分账，超支即停并落读数 | G6 |

---

## 3. 反证条件（出现就说明「不够」，我必须在交付里直说）

- G1：连续两次 24h 跑不到 10 个，或自主任务全是启动时给定的。
- G2：新目标需要人工拆解或人工派活才能推进。
- G3：判据复跑出现不一致，或需要生成方自己解释才算通过。
- G4：换领域必须改代码。
- G5：三次结论走出三条路，且差异不是等价表述。
- G6：有任何任务没有预算上限，或有超支未止损的任务。

---

## 4. 「更优」怎么判

「最优」不可证（见 [`OPTIMALITY.md`](OPTIMALITY.md)）。对外只能声称 **L1 占优**或 **L2 未发现更优**，并且必须附候选集、预算、判据版本、差值四项。

## 5. 现在到哪了

跑 `python3 scripts/bench.py` 看实时读数；历史在 `reports/bench-*.json`。

| 判据 | 状态 | 关键证据 |
|---|---|---|
| G1 自主性 | **红（时间门）** | 常驻进程在跑，需满 24h；预计 2026-11-20 18:31 写出 `reports/liveness-*.json` |
| G2 组织性 | 绿 | 6 角色 × 2 阶段，真模型执行，12 派活 / 13 交接 / 2 次验拒 / 2 次返工 |
| G3 判据能力 | 绿 | 判据运行时 + daemon 通电；生成方无权注册，未注册判据即判红 |
| G4 知识扩展 | 绿 | arXiv 取 2 领域各 3 条；RAG 引用 4 条全部可溯源 |
| G5 不漂移 | 绿 | 同任务 3 次，结论条目重合率 1.0（**前提：受控词表**） |
| G6 成本可控 | 绿 | 预算超支即停有测试；记账用真实 usage（实测 166 tokens） |

**当前 5/6，判定「不够」。** 唯一红项是墙钟约束：G1 要求真实跑满 24 小时，不是代码问题。
跑满后 `bench.py` 会自动读报告判绿，不需要改任何代码。

**已知弱化（绿的成色）**：G2 的返工质量无人复核；G4 抓的是元数据、未读全文；G5 的可复现依赖受控词表；G6 的真实 usage 只覆盖走 `complete_usage` 的调用。
