## 0. 判定口径

不按「模块写完」算完成，按**读数**算。全项目只有三条总判据：

| # | 总判据 | 怎么读 | 验的是 |
|---|---|---|---|
| **G1** | 无人在场跑 24h，系统自主发起且有进展的任务 ≥ 10 | 账本 `autonomous_dispatch` 计数 | 活性 |
| **G2** | 注入的已知错误，被独立 Verifier 打回率 ≥ 80%，且不靠人工 | 注入测试集回读 | 有效性 |
| **G3** | 杀掉主节点/实例，重建后能从断点继续，知识底座哈希一致 | 恢复演练脚本退出码 | 不腐坏 |

三条达不到，任何里程碑都不许自称完成。「跑通了」不算，读数才算。

## 1. 里程碑

### M0a 测量仪（stub 主体，不接真模型）

**为什么排第一**：整套设计的核心假设是「压力结构能产生主动性」。这是唯一能用最小代价证伪的一条——如果连 stub 主体都跑不出自主发起，接上真模型只会把「演得像」误读成「真有」。先造尺子。

**交付**
- `xm/ledger.py` — 收益账本：append-only，**只有审计方写**，被考核方只读（对应 §15.1、§15.8）
- `xm/criteria.py` — 判据注册表：带版本号；升格必须过 calibration（§15.8(3)）
- `xm/gates.py` — 阶段准出：需求/设计/实现/定位/运维（§15.4）
- `xm/runner.py` — 最小调度：3 角色 + 心跳 + 无进展检测 + 自动降级（§15.2）
- `tests/` — 判红测试，含一条**反例测试**：关掉无进展检测后必须变红

**判红判据**
```bash
python3 -m unittest discover -s tests -q        # 全绿
# 反例：注入 XM_DISABLE_LIVENESS=1 时，降级测试必须失败
```

**退出**：20 轮 stub 跑完，能读出 3 个数（自主发起 / 自我纠偏 / 被打回比例）。

### M0b 真主体（接真模型跑 24h）

**交付**：把 stub 换成真 agent，跑一个可判定的真任务（修一个已知 bug 或复现一个已知实验）。

**判红判据**：G1 达标，且三个读数与对照组（单 agent、派活才动）有显著差异。

**退出**：读数写进 `reports/m0b.json`。

> M0a/M0b 分开的原因：24h 真模型运行当天给不出读数。先证明尺子能量出差异，再用尺子量。

### M1 骨架 + 指标 + 工单总线（对应设计文档 §11 步骤 1–3）

- 项目骨架、5 项健康指标采集落库、结构化工单总线（JSON Schema）
- **判红**：非法工单被拒收；5 项指标各有一条采集测试

### M2 六角色 + 编排引擎（§11 步骤 4–5）

- **判红**：给一个目标，自动建队、跑完一个子任务、销毁临时角色；角色销毁后账本仍可审计

### M3 校验与隔离（§11 步骤 6）

- 弱 + 中两级；Verifier 进程级隔离
- **判红**：G2；给 Verifier 一条含生成方思维链的输入，必须被过滤

### M4 灰度与回滚（§11 步骤 7）

- **判红**：推一个坏变更，自动回滚到上一版且状态一致（对拍测试）

### M5 治理与自举（§11 步骤 8 + §13）

- L1 双节点 + 热备、越级告警、恢复演练
- **判红**：G3

## 2. 关键路径

```
M0a ──> M0b ──> M1 ──┬──> M2 ──┐
                     └──> M3 ──┴──> M4 ──> M5
```

- M0 放最前：代价最小、信息量最大，而且它是唯一能证伪核心假设的一步。
- M1 在 M2 前：角色没有工单总线和指标采集，无法量化，也无法拒收。
- M2 与 M3 可并行，但 M3 依赖 M1 的 schema。
- M4 依赖 M2 的版本化；M5 最后，因为它要前面所有层都稳。

## 3. 贯穿项（每个里程碑都要做，不是某个阶段）

1. 承载体 Contract 补齐：38 条表逐条补「输入/输出/失败信号/拒收规则」，补不出标 `TODO` 并降级（§15.5）
2. 判据注册表维护：新增判据必须带版本 + calibration 结果
3. 审计账本不中断：任何阶段都不许出现「这段时间没记账」

## 4. 明确不做（MVP 边界）

L2+ 元治理、强校验（形式化验证）、物理世界接口、AI 版自迭代引擎（先用规则引擎）。
写在这里是为了防止范围漂移，不是为了将来补。

---

## 5. 前置决策（不定完不许进 M1）

1. **账本由谁写**：审计方独立写，被考核方只读。否则被考核方刷账本，G1 的读数不可信。
2. **无进展的 N 与 24h 窗口怎么切**：N 定不下来，「自主发起」就无从计数。
3. **G1/G2/G3 的阈值先钉死**：按本文上方数值执行，跑完 M0b 才允许调；**禁止跑完再看读数定阈值**。

---

## 6. 风险

| 风险 | 影响 | 先手 |
|---|---|---|
| 账本被被考核方刷 | 活性读数不可信 | M0a 就把记账方与被考核方隔离 |
| 判据自己升自己 | 自评越比越松 | 升格必须「多抓到一条旧版漏掉的错」 |
| 24h 模型成本失控 | 实验做不完 | M0b 设 token 上限，超限即停并落读数 |
| 把「演得像」当「真有」 | 整条路线误判 | M0a 用 stub 先证明机制能产生差异，再换真模型 |
